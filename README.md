# Test Case Documentation Agent

A local Streamlit app that turns a screen recording (uploaded or captured live)
or a plain-English step guide into a formal Word test case document, powered
by Claude Code. It matches your own template's structure when you provide
one, and backs each expected result with a real screenshot as evidence.

## Features

- **Video Upload mode** - upload a screen recording; frames are sampled and
  the most relevant one is embedded into each test case's Expected Result.
- **Manual Step Guide mode** - type the steps in plain English; Claude drives
  a real headless (or headed, for visual verification) browser through them
  and captures screenshots as evidence, highlighting the element each step
  acted on.
- **Built-in screen recorder** - a "Record" button opens a small floating
  control panel plus your target page in a new tab, so you can log in first,
  then record. The finished recording is picked up automatically, no page
  refresh needed.
- Optional JIRA ID label, optional reference `.docx` template to match, and
  a progress bar during generation that ends in a success message and a
  download button for the finished document.
- A polished, animated terminal-style UI (typing hero prompt, pulsing status
  glow, scanning dividers) - just visual polish, no functional effect.

## Prerequisites

- Windows, Python 3.10+, and [Node.js](https://nodejs.org/) (for the local
  Claude Code CLI and Playwright).
- A Claude subscription that `claude auth login` can authenticate against.

## Setup

```bash
# 1. Install Node dependencies (installs the Claude Code CLI, the local
#    Playwright MCP server, and docx)
npm install

# 2. Log the local Claude Code CLI into your account
.\node_modules\@anthropic-ai\claude-code\bin\claude.exe auth login

# 3. Install Python dependencies
pip install -r requirements.txt

# 4. Install the headless browser used for Manual Step Guide mode
npx playwright install chromium
```

> **Playwright MCP stays pinned:** Manual Step Guide mode runs the
> `@playwright/mcp` package installed by step 1 directly (no `npx ...@latest`),
> so every generation skips a network round-trip to the npm registry. Update
> it deliberately with `npm update @playwright/mcp` rather than it changing
> underneath you on every run.

> **Windows Store Python note:** if `python`/`pip` on your PATH resolve to
> the sandboxed Microsoft Store Python, it can silently fail to see files
> outside a few whitelisted folders (including the Claude CLI). `run_app.ps1`
> hardcodes a path to a non-sandboxed Python install - update that path for
> your machine, or just run `streamlit run app.py` with your own real
> Python/pip instead.

## Running

```bash
powershell -ExecutionPolicy Bypass -File run_app.ps1
```

This opens `http://localhost:8501` in your browser.

## Project layout

| File | Purpose |
|---|---|
| `app.py` | Streamlit UI |
| `pipeline.py` | Prompt building, frame extraction, headless Claude invocation |
| `recorder.html` / `recorder_server.py` | Built-in screen recorder + its local server |
| `mcp_config.json` | Playwright MCP config template for browser automation |
| `.streamlit/config.toml` | App theme |

Runtime folders `.runs/` (your recordings, uploads, generated docs) and
`node_modules/` are git-ignored - the former for privacy, the latter because
it's regenerated by `npm install`.
