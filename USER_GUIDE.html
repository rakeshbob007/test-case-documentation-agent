Getting the Agent Running

I Clone → running app

Part 1 — Environment setup

  1. Clone the repository

    git clone https://github.com/rakeshbob007/test-case-documentation-agent.git
cd test-case-documentation-agent

  2. Install Node dependencies

    Installs the Claude Code CLI and the Playwright MCP server locally to the project (not globally, and not via npx ...@latest) — avoids Windows PATH and corporate-security issues with the global npm install location, and skips a network round-trip on every generation.

    npm install

  3. Log the local Claude Code CLI into your account

    .\node_modules\@anthropic-ai\claude-code\bin\claude.exe auth login

    Follow the browser login prompt that opens.

  4. Install Python dependencies

    pip install -r requirements.txt
    Windows Store Python warning: if plain python/pip on PATH resolve to the sandboxed Microsoft Store Python, it can silently fail to see files outside a few whitelisted folders — including the Claude CLI itself. If you hit "claude CLI not found" later, locate your real Python install (commonly C:\Users\<you>\AppData\Local\Python\bin\python.exe) and use that explicitly.

  5. Install the headless browser (Manual Step Guide mode)

    npx playwright install chromium

  6. Point the launcher at your Python install

    Open run_app.ps1 and confirm $py matches your real (non-sandboxed) Python executable:

    $py = "C:\Users\<you>\AppData\Local\Python\bin\python.exe"
& $py -m streamlit run "$PSScriptRoot\app.py"

  7. Open the main page

    powershell -ExecutionPolicy Bypass -File run_app.ps1

    Starts the Streamlit server and opens http://localhost:8501 — the main page of the agent.

II Using the app

Part 2 — Functional flow

The main page walks through three numbered steps, plus a Generate action.

Step 1 — Task details

JIRA ID (optional): a text label (e.g. PROJ-1234) stamped onto the generated document — no live JIRA connection is made.

Reference template (optional, .docx): upload your team's existing test case template. If provided, Claude reproduces its exact table structure and headers, only filling in new content; otherwise a clean standard table is generated (Test Case ID, Title, Preconditions, Test Steps, Test Data, Expected Result, Priority).

Step 2 — Workflow source

A · Video Upload

  1. Upload a recording (mp4/mov/avi/mkv/webm), or click 🔴 Record.
  2. Record popup (now a wide dialog): enter a save folder on its own full-width line + target URL, click Proceed — the target page and a floating recorder panel open.
  3. Log in / navigate, click Start, use Pause/Resume as needed, then Stop.
  4. Recording uploads automatically; close that tab and switch back.
  5. Main page auto-detects the finished recording within ~2 seconds — no manual refresh. Discard to re-record.
  6. Adjust max frames (5–40) — more frames catch more detail but take longer.

B · Manual Step Guide

  1. Type the workflow in plain English, one instruction per line.
  2. Choose Headless (fast, invisible) or Headed (visible, watch it run live).
  3. Claude drives a real Playwright browser through your instructions, highlights the element each step acts on, and screenshots it as evidence.

Additional guidelines (either mode): free-text extras layered on top, e.g. "also cover mobile viewport sizes."

Test case scope: step-by-step functional only, or functional + edge/negative cases.

Step 3 — Save location

Click Browse... for a native folder picker, or type the destination path directly. Generate stays disabled until both a workflow source and an output folder are set — and pulses gently once it's ready to go.

Generate

A progress bar tracks the run while, under the hood, the app extracts frames (or drives the live browser), builds a detailed prompt (template + JIRA ID + guidelines + scope), runs the local Claude Code CLI headlessly, and Claude writes the test cases — embedding the single most relevant image into each Expected Result cell, auto-resized, switching to landscape if needed to avoid overflow — then saves the final .docx to your chosen folder.

When it finishes, the progress bar reaches "Done" and a green success message plus a Download the generated document button appear right on the main page — the file is also already sitting in the output folder you selected, ready to attach to JIRA or send to the customer.
